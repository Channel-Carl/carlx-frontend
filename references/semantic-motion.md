# 语义动效：让播放解释内容

实现动效时读取。吸收归藏按元素角色编排的思路，按关系设计播放，而不是复制其页面类名、选择器或固定元素数量。无动效是工作界面和阅读内容的有效选择；用户要求丰富演示动效时应实际实现，不以全页淡入代替。

## 按内容关系组合

| 意图 | 编排方式 | 应保持稳定的内容 |
|---|---|---|
| 建立结构 | 核心/基础先出现，依赖层随后建立，连线呈现依赖 | 层级名称、实际布局与最终边界 |
| 讲解过程/时间 | 轴/路径建立，再依顺序强调节点与解释 | 真实时间间距、已完成步骤与上下文 |
| 比较两侧 | 共同比较框架先建立，两侧对应项接续或同时出现，差异最后强调 | 同一量纲、位置与标签，不能交换两侧 |
| 显示大小/变化 | 轴与单位可见，数据标记从实际基线到目标，读数落在最终值 | 零线、负值方向、准确最终几何 |
| 解释整体与贡献 | 总体先定位，再解释组成或增减，最后收束到结果 | 真实比例/累计值，不逐项伪造整段趋势 |
| 展开关系 | 起点/核心先出现，再沿必要关系显示节点和连线 | 连线方向、标签与不同权重含义 |
| 强调关键结论 | 主体就位后用局部对比/描画/短暂停顿突出关键对象 | 其他证据可读，不制造长时间不可见 |
| 操作反馈 | 输入后立即反馈，连续状态保持空间关系，完成/错误清楚呈现 | 焦点、控件位置与可继续的任务 |

这些意图可以组合成一个章节的时间线。例如演示柱线组合图：先呈现坐标与单位 → 柱与线按同一时间窗口展开 → 标出异常月份 → 展示有依据的解释。不要把图形、标签、数字全部一起缩放，造成读数变形。

归藏的 stack-build 可迁移为依赖建立，duo-mirror 为共同框架对比，timeline-walk 为时间推进，three-forces 为主论点与证据，bar-grow 为按基线增长；名称只是来源说明，生成作品不必使用这些名称或对应布局。三个证据不是必须三张卡，五个节点也不是固定数量。

## 根据作品控制强度

产品 UI：以用户动作驱动为主，保持即刻响应；数据刷新不让整张仪表盘每次重新入场。阅读报告：核心证据与正文直接可读，筛选与局部解释可以过渡。网站/作品展示：将表达集中在主视觉或有意义的转折。演示：允许分阶段讲解，观众能看清当前重点，同时有可用的前进、后退或跳过。

建议起点：反馈约 100–180ms，界面过渡约 180–320ms，演示片段约 400–800ms，同组错峰约 60–140ms。以上是本 skill 调校建议，不是所有平台的标准；按距离、观看场景和数量调整。长列表按组或区域播放，不无限累加延迟；主要内容不应等待数秒才可读。

优先自然减速与短距离移动。数字滚动必须保持精度、符号、单位和最终值；没有分析意义时直接显示数值更清楚。绘制数据曲线不能改变真实形状。负柱从零线朝负方向增长，瀑布增减从对应累计起点变化，不能统一从绘图区底部冒出。

## 演示编排要落实到对象

演示在逐页计划中记录“稳定框架 → 证据变化 → 局部聚焦 → 解释/收束”，按实际问题删减或组合阶段。写出对象、属性、顺序、并行关系与触发方式，例如“零线保持；当前季度柱高由零到真实值；现金流路径沿季度展开；异常季度标注随后出现”。“图表平滑增长”“物理阻尼高级动效”不是可执行计划。

实现时让每个需要讲解的场景有自己的时间线/关键帧序列；共用只负责节奏和生命周期，证据动画由当前图的含义决定。复杂编排优先选单个支持时间线的实现（如项目已有 GSAP 或 Motion），用命名阶段和重叠位置管理，并让该图的数据模型提供最终几何。不要给所有后代元素套同一个 opacity + translateY + stagger，也不能只有翻页动画而声称图表已展开。

| 讲解任务 | 一个可实现的编排 | 容易损坏的地方 |
|---|---|---|
| 趋势与转折 | 时间框架稳定；数据路径沿真实时间区间揭示；转折点局部标注；解释接续 | 揭示裁切同时遮住坐标标签；将多条不同量纲路径变成假相关运动 |
| 基准与实际差距 | 同一比较框架；基准组先定位；实际组从共同零线建立；差距括线与说明最后落点 | 两侧全图相向飞入，数字和轴一起移动导致无法比较 |
| 累计贡献 | 起点就位；变化段沿累计起点依次建立、连接线按贡献顺序出现；终点及主要贡献强调 | 负段从页面底部生长，或已出现段落继续改变真实位置 |
| 多群体构成差别 | 框架/系列说明先定位；完整构成按群体建立；焦点标签或描边强调关键份额；比较说明接续 | 逐段增长时把临时比例当作完整整体；标签跟随缩放变形 |
| 依赖与决策路径 | 核心条件/输入就位；真实路径建立；相应节点随后出现；所选路径局部强调 | 关系没有方向却画成流程，或随机连线营造技术感 |

表中不是必须五种效果，也不要求每页有四段。相同问题可复用同一编排；不同语义需要改变对象与阶段，不能只调整延迟。在克制的咨询分析外观中，动画仍能通过基线、路径、差距、贡献与焦点清楚解释内容，无需弹跳、发光或背景旋转。

长讲解按阶段暂停/继续可以更适合现场，短编排可以自动完成；根据观看方式确定，不自动添加额外控制协议。已有前后页操作继续用于翻页，不悄悄将其重定义为逐元素推进。跳过动画应可直接得到完整证据。

## 实现与生命周期

遵循项目现有栈。简单反馈可用 CSS 或 Web Animations，复杂讲解时间线可用项目已有 GSAP/Motion；先检查依赖，避免为每种效果混用库。本 skill 不强制安装某个库，也不内置归藏代码。

最终静态布局是基础，动画层只控制暂时状态。基础 CSS 默认让内容可读；只有动画机制已成功初始化时才应用入场初态。不可依赖远程库加载成功才能显示正文。

一个场景/页/组件由一个生命周期管理其时间线、计时器与监听器：切页、关闭、卸载或快速切换时停止旧播放，恢复准确静态布局；返回时是否重播按作品行为决定。反复创建不能叠加处理器。需要暂停/重播时让控制作用于当前场景。

数据几何、布局 transform 和动画 transform 分离：必要时用内部包装层或组合变换，避免覆盖节点定位或文字居中。停止、跳过、减少动画和导出状态必须得到同一最终数值与布局。

`prefers-reduced-motion` 下直接呈现完整信息与操作反馈，不保留大幅位移、闪烁或长时间等待。手动静态模式只在持续背景/丰富演示有实际用途时提供；启用后停止不必要的 RAF、计时与动画，内容直接到最终态，不要求所有网站都增加 B 键。

只有当前可见场景运行持续效果，离开视口/切到后台按需停止。优先 transform/opacity，确需 SVG 路径/数据几何动画时控制复杂度；不要为了“高级”默认每页持续 WebGL。

## 验证实际行为

检查首屏/当前页能否播放、完成后读数与布局是否准确、快速来回切换是否叠加或残留、减少动画是否直接可读。有重播、跳过或数据更新时验证这些实际入口；未实际运行只能说明实现意图，不能声称动效已验收。

演示至少选两页不同证据关系的代表场景（全篇只有一种关系时取一页），在浏览器中看起始、关键中间阶段和最终状态。中间阶段应出现与计划对应的数据标记、路径、差距或焦点变化；仅整页透明度/位移改变说明编排尚未落实。终点截图无法验证动效质量。交付说明实际查看的场景和行为，未检查的不要写成已通过。
