# 内容布局与复杂图表

确定方向后组织内容时读取。这里的结构是推导示例，不是必须选择的模板库；没有布局 ID、登记范围或页数配额。

## 先确定信息关系

为页面、章节或演示页确定主要任务/问题、必要证据、解释与操作，再分配区域。最重要的内容有足够空间，不必始终最大字号。高密度内容保持完整，采用清楚的分组与渐进展开，而不是一律砍成三个要点。

| 内容关系 | 可推导的结构 | 空间与阅读顺序的重点 |
|---|---|---|
| 一个结论及证据 | 短结论 + 主要图/表 + 紧邻注释 | 证据占主体，来源与单位保持可见 |
| 两种方案/前后变化 | 共同比较维度 + 并列区域或对照表 | 同一顺序与量纲，重要差异容易定位 |
| 时间/过程 | 轴线、步骤或泳道 + 对应事件 | 日期/依赖决定位置，不虚构等间隔 |
| 系统与关系 | 层级、拓扑或矩阵 + 局部说明 | 节点/连线有含义，标签不压在交叉线上 |
| 长篇阅读 | 主阅读栏 + 相关图表/引用 + 目录 | 窄屏回到自然顺序，不把旁注变成散乱正文 |
| 操作与监控 | 筛选/状态 + 主工作区 + 详情/反馈 | 主要操作可达，重复数据区稳定，加载/空/错误可理解 |
| 品牌与作品展示 | 特征主视觉 + 作品/证据 + 必要行动 | 使用真实主体，章节按内容形成变化 |

卡片适合独立实体、独立操作与重复比较；表格适合逐项查找和多属性精确比较；图表适合发现模式。不要为了某种风格将所有表格替换成信息损失的装饰图。

## 页面容量与响应

普通网站和工作界面按内容重排：多栏合并、详情切换、导航折叠；视觉顺序、DOM 与键盘顺序相容。以内容开始拥挤的位置决定断点，不把桌面画面统一缩成手机小图。复杂表格可在明确区域横向滚动，并保留表头与阅读提示。

阅读报告可以滚动、分章节和定位；演示按既定舞台观看。固定舞台使用统一整体缩放，不逐元素依视口改变位置；不能借滚动或裁切掩盖一页超载。拆页时保留问题、关键结果和前后上下文，页数有硬约束时先重组、压缩重复话语或利用附录，无法兼容再说明具体冲突。

设计时预留标题、绘图区、轴/标签、图例、解释和来源的空间。实际长标签、负值、极端值、最长标题和最密集区域比占位矩形更能暴露容量问题。需要更大绘图区时降低装饰面积或改变布局，不优先缩小文字。

## 图表按问题选，不按预设选

| 分析问题 | 候选图形 | 关键边界 |
|---|---|---|
| 类别比较/排序 | 条形、点图、分组条形 | 长中文标签优先横向；长度编码通常零起点 |
| 时间趋势 | 折线、阶梯、面积、小多图 | 时间顺序和间距真实；缺失值不能补成零 |
| 部分与整体 | 堆叠条形、100% 堆叠、树图、少量类别的环形 | 比例有共同分母；组成需完整或明确其他/未知 |
| 从起点到终点的变化贡献 | 瀑布图、桥接图 | 浮动段与累计值计算一致，总额与增减区分 |
| 分布/离群 | 直方、箱线、点分布 | 分箱/样本数/统计定义清楚 |
| 两变量关联 | 散点、热力、小多图 | 关联不等于因果，量纲与样本明确 |
| 不同单位的同步趋势 | 对齐小多图、必要时双轴组合图 | 每系列归属明确，双轴不能制造相似相关趋势 |
| 流向/层级/连接 | Sankey、树、网络、关系矩阵 | 有量才编码宽度；无量关系不要伪装为流量 |

以上不是白名单。允许其他适合的图形；选复杂图是为了回答问题，不为展示技术。类别很多可用排序、分组、筛选或小多图，不能只保留前三名而不说明。

## 复杂图的实现约束

**SVG、Canvas 和图表库均可使用。** SVG 可直接放 `<text>`、坐标轴、图例和标签；标签选 HTML 或 SVG 根据可读性与交互需要决定。简单或高度定制图可用 SVG；大量点或复杂交互可使用项目已有的成熟图表库。不要让用户选择实现库，也不要要求依赖某个原版 skill 的模板。

建立单一数据模型与尺度映射，图形、提示、计数、表格使用同一来源及业务计算。数据清洗、排序、单位变换有明确依据；未知、缺失和零分别处理。演示数据明确标记，不补造支持结论的数值。

瀑布图先计算累计值：增减段起止为 previous 与 previous + delta；像素位置映射两者，段高度是映射差的绝对值。总额从基线到总值，与浮动段区分；检查起点加全部变化等于终点，舍入差异注明。

双轴确有必要或用户明确要求时支持。两条轴分别标单位、范围和系列归属，颜色/线型/图例共同匹配；不得通过选择轴范围制造同涨同跌或交叉点的错误暗示。目标是比较趋势而非精确跨单位读数时，可考虑对齐小多图或有明确基期的指数图；不擅自替换用户指定的图形。

关系图先定义节点与边的含义、方向和必要权重；按层级/聚类/地理/时间等真实关系排布。密集图用过滤、展开或局部聚焦，解释当前范围；不能随机连线凑出科技感。流程图的步骤顺序与关系图的拓扑关系不是同一类数据。

## 将图表融入选定风格

沿用作品的字体角色、中性色温、线条与注释语法；让数据标记强于背景网格。图表背景可以为读数使用同体系的干净 surface，纸纹/光效不进入绘图区。

分类色在整个作品中固定映射，连续色表示有序值，发散色有明确中点。正负、状态与品牌强调分别定义，不能把颜色外观当成业务含义；颜色同时配线型、标记、标签或直接注释。主色板的 accent 只负责视觉身份，不限制数据色数量，也不保证细线对比合格。

标题说清图表回答什么，结论必须有数据支持。标出单位、范围、时间、口径及来源。给关键点注释时让注释靠近对象并留出避让空间，不用满屏引线。动态图在静态最终态仍可理解，重要信息不能只存在于 hover。

对于大量数据或交互图，提供必要的文字结论/数值摘要及可访问的读数途径；不必为每张小图复制整份明细表。手机需要时提供局部滚动、放大或详情，保持标签、筛选与关键结论可用。

## 核验重点

核对数据总额、负值与缺失、尺度与单位、堆叠顺序、图例映射、标签位置及动态更新。每种复杂图选择其关键不变量验证，例如瀑布图累计终值、环形比例总和、双轴系列对应、关系图边含义；不通过肉眼柱高“差不多”替代计算。

看实际渲染中的最长标签和最密集图，确认背景/标记对比、静态最终态与可用交互。筛选影响关联图时保持同一口径，或明确哪些视图不受筛选影响。
